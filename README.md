# ระบบประเมินการตัดสินใจไปพบแพทย์ของผู้สูงอายุ

โครงงานปี 4 — เว็บแอปประเมินความเสี่ยงเบื้องต้นว่าผู้สูงอายุควร **ไปพบแพทย์ทันที /
นัดพบแพทย์เร็วๆ นี้ / เฝ้าระวังอาการที่บ้าน** พัฒนาด้วย [Streamlit](https://streamlit.io)
พร้อมระบบเก็บข้อมูลนำร่อง (Pilot Data Collection) และหน้าสรุปสถิติสำหรับใช้ในรายงาน

> ⚠️ ใช้เพื่อการศึกษา/โครงงานวิจัยเท่านั้น ไม่ใช่เครื่องมือวินิจฉัยทางการแพทย์

## คุณสมบัติ

- **หน้าแบบประเมิน**: ครอบคลุม 6 ด้าน — สัญญาณอันตราย, ADL/IADL แบบย่อ,
  ความเสี่ยงหกล้ม, สภาพจิตใจ/อารมณ์, การใช้ยา, อาการทั่วไป/โรคเรื้อรัง
- **บันทึกข้อมูลจริง** ทุกครั้งที่ประเมินจะถูกเก็บลง `data/assessments.csv`
  เพื่อนำไปใช้เป็นข้อมูลนำร่อง (pilot data) ของโครงงาน
- **หน้าสรุปข้อมูล/สถิติ**: กราฟการกระจายระดับความเสี่ยง, คะแนนเฉลี่ยตามช่วงอายุ,
  แนวโน้มตามเวลา, ตารางข้อมูลดิบ และปุ่มดาวน์โหลด CSV — ใช้ประกอบบทที่ 4 ของรายงานได้ทันที

## ที่มาของเกณฑ์การให้คะแนน (สำหรับอ้างอิงในบททบทวนวรรณกรรม)

เกณฑ์คะแนนในไฟล์ `utils.py` ออกแบบโดยอิง**แนวคิด**จากเครื่องมือ/หลักการที่ใช้ทั่วไป
ในงานประเมินผู้สูงอายุ ได้แก่:

| หมวด | แนวคิดที่อ้างอิง |
|---|---|
| สัญญาณอันตราย | หลักการคัดกรองความฉุกเฉิน (Triage) |
| ความสามารถทำกิจวัตร | ADL / IADL (Activities of Daily Living) |
| ความเสี่ยงหกล้ม | ปัจจัยเสี่ยงหกล้มในผู้สูงอายุ (ประวัติหกล้ม, อุปกรณ์ช่วยเดิน, การใช้ยาหลายชนิด) |
| สภาพจิตใจ | แนวคิดการคัดกรองภาวะซึมเศร้า/อารมณ์เบื้องต้นในผู้สูงอายุ |

**ข้อควรทำต่อก่อนใช้เก็บข้อมูลจริง:**
1. นำแบบประเมินนี้ให้อาจารย์ที่ปรึกษา/ผู้เชี่ยวชาญตรวจสอบความเหมาะสมของคำถามและน้ำหนักคะแนน
2. อ้างอิงเครื่องมือมาตรฐานฉบับเต็ม (เช่น ชื่อเครื่องมือ ADL/Fall Risk ที่เลือกใช้จริง) ในบทที่ 2
3. หากเก็บข้อมูลกับกลุ่มตัวอย่างจริง ควรขอรับรองจริยธรรมการวิจัยในมนุษย์ (EC) ตามระเบียบของสถาบัน
   แม้จะเป็นคำถามความเสี่ยงต่ำ ก็ควรแจ้งวัตถุประสงค์และขอความยินยอมจากผู้ตอบทุกครั้ง
4. ใช้ **รหัสผู้ตอบ** แทนชื่อจริงเพื่อรักษาความเป็นส่วนตัว (ระบบตั้งค่าให้กรอกรหัสอยู่แล้ว)

## โครงสร้างไฟล์

```
elderly-doctor-decision/
├── app.py                          # หน้าแรก (Home)
├── utils.py                        # ตรรกะการให้คะแนน + จัดการไฟล์ CSV (ใช้ร่วมกันทุกหน้า)
├── pages/
│   ├── 1_📝_แบบประเมิน.py           # หน้ากรอกแบบประเมิน + บันทึกข้อมูล
│   └── 2_📊_สรุปข้อมูล.py           # หน้าสรุปสถิติ/กราฟ + ดาวน์โหลด CSV
├── data/
│   └── .gitkeep                    # โฟลเดอร์เก็บ assessments.csv (ไม่ commit ข้อมูลจริงขึ้น GitHub)
├── requirements.txt
├── .gitignore
└── README.md
```

## วิธีรันบนเครื่องตัวเอง

```bash
git clone https://github.com/<YOUR-USERNAME>/<YOUR-REPO>.git
cd <YOUR-REPO>
pip install -r requirements.txt
streamlit run app.py
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:8501` แล้วใช้เมนูด้านซ้ายสลับไปหน้า "แบบประเมิน" และ "สรุปข้อมูล"

## วิธีอัปโหลดขึ้น GitHub

```bash
git init
git add .
git commit -m "Initial commit: elderly medical decision support app with data collection"
git branch -M main
git remote add origin https://github.com/<YOUR-USERNAME>/<YOUR-REPO>.git
git push -u origin main
```

> หมายเหตุ: ไฟล์ `data/assessments.csv` ถูกกันไว้ใน `.gitignore` แล้ว
> เพื่อไม่ให้ข้อมูลจริงของผู้ตอบแบบสอบถามหลุดขึ้น GitHub สาธารณะ

## วิธี Deploy ขึ้น Streamlit Community Cloud (ฟรี)

1. เข้า https://share.streamlit.io แล้ว Sign in ด้วยบัญชี GitHub
2. กด **"New app"** เลือก repository, branch (`main`), ไฟล์หลัก (`app.py`)
3. กด **Deploy** จะได้ลิงก์เว็บ เช่น `https://<your-app-name>.streamlit.app`

⚠️ **ข้อจำกัดสำคัญ**: พื้นที่จัดเก็บไฟล์บน Streamlit Community Cloud เป็นแบบชั่วคราว
(ephemeral) — หากแอปรีสตาร์ท ข้อมูลใน `assessments.csv` ที่เก็บผ่านเว็บที่ deploy ไว้
**อาจหายไป** วิธีแก้สำหรับการเก็บข้อมูลนำร่องจริง:
- ดาวน์โหลดไฟล์ CSV จากหน้า "สรุปข้อมูล" มาสำรองไว้เป็นระยะ หรือ
- รันแอปบนเครื่องตัวเอง/โน้ตบุ๊กขณะลงพื้นที่เก็บข้อมูลจริง (แนะนำสำหรับ pilot testing) หรือ
- ต่อยอดให้บันทึกลงฐานข้อมูลถาวร เช่น Google Sheets (ผ่านไลบรารี `gspread`) หรือฐานข้อมูล
  บนคลาวด์อย่าง Supabase/Firebase แทนไฟล์ CSV ในเครื่อง

## แนวทางต่อยอด

- เพิ่มระบบ login แยกสิทธิ์ผู้เก็บข้อมูล/ผู้ดูแลระบบ
- ย้ายจาก CSV ไปใช้ฐานข้อมูลถาวร (SQLite/PostgreSQL/Google Sheets) เพื่อกันข้อมูลหาย
- วิเคราะห์ความสัมพันธ์ทางสถิติเพิ่มเติม เช่น correlation ระหว่างอายุกับคะแนนความเสี่ยง
  หรือทดสอบสมมติฐานด้วย t-test/ANOVA เพื่อใช้ในบทที่ 4-5
- ทำแบบสอบถามความพึงพอใจของผู้ใช้งานระบบ (System Usability Scale) ประกอบการประเมินโครงงาน
